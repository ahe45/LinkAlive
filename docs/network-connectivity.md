# 감시 PC의 외부 연결 검사

관리자 계정의 **감시 네트워크** 메뉴(`/network`)에서 기준 주소와 복구 요약 채널을 설정합니다. 일반 계정에는 메뉴가 표시되지 않으며 페이지와 API 모두 관리자 권한을 검사합니다.

복구 요약 채널은 모니터 등록 화면과 동일한 Telegram 채널 카드에서 선택합니다. 채널 이름과 수신 대화방 ID를 확인하고 여러 채널을 선택할 수 있습니다. 선택은 설정 저장 시 반영됩니다.

기준 주소 옆의 **연결 테스트** 또는 **전체 연결 테스트**로 저장 전 입력값을 검사할 수 있습니다. 주소별 연결 가능 여부, HTTP 상태 코드, 소요 시간 또는 오류를 표시합니다. 자동 검사와 동일한 HEAD·5초 제한·리다이렉트 미사용·공인 주소 정책을 적용합니다. 테스트는 설정, 자동 연결 상태, 중단 이력, 대상 장애 또는 알림을 변경하지 않습니다. 수동 테스트는 API 서버 PC에서 실행하며 결과에 실행 PC 이름을 표시합니다. API와 워커가 다른 PC에 배치된 환경에서는 수동 결과와 자동 감시 결과의 관측 위치가 다릅니다.

처음에는 비활성화되어 있습니다. 서로 다른 운영사·네트워크의 공인 HTTP/HTTPS 주소 2~5개를 등록한 뒤 활성화하세요. 호스트 중복, 인증정보, 쿼리, fragment, 사설 IP는 허용하지 않습니다. 실행 시에도 기존 URL 정책으로 DNS 결과와 공인 주소 여부를 검증합니다. 서로 다른 호스트가 실제로 서로 다른 네트워크인지는 관리자가 확인해야 합니다.

- 워커가 평상시에는 약 60초 간격으로 기준 주소에 HEAD 요청을 보냅니다. 모든 기준 주소가 네트워크 연결에 실패하면 약 10초 간격으로 전환하고, 한 곳이라도 HTTP 응답을 받으면 60초 간격으로 돌아갑니다. 요청당 제한 시간은 5초이며 리다이렉트는 따라가지 않습니다. HTTP 4xx/5xx를 포함한 응답 수신은 연결 가능으로 판단합니다. 연결 중단이 아직 해소되지 않았다면 일시적으로 판정할 수 없는 검사 결과가 나와도 10초 간격을 유지합니다.
- 대상 연결 실패 시에는 정기 검사 간격을 기다리지 않고 기준 주소를 즉시 확인합니다. 이 결과도 다음 정기 검사 시점에 반영합니다. 정기 검사 간격과 별개로 복구 요약 대기 처리는 약 10초 간격으로 계속합니다. 설정 저장은 다음 기준 검사 시점까지 최대 약 60초가 걸릴 수 있습니다.
- 대상에서 HTTP 응답을 받지 못한 네트워크 오류가 나면 기준 주소를 확인합니다. 모두 네트워크 연결에 실패하면 감시 PC 외부 연결 이상을 의심하고 해당 검사를 `INCONCLUSIVE`로 기록합니다. 기준 검사 자체를 판정할 수 없어도 대상 장애 확정은 보류합니다.
- 응답 코드·내용 불일치와 같이 대상에서 응답을 받은 실패는 기존대로 처리합니다. 기준 주소에 접속할 수 있어도 특정 대상까지의 경로가 정상이라고 보장하지 않습니다.
- 판정 보류는 대상의 장애·복구 상태와 연속 성공·실패 횟수를 변경하지 않습니다. 대시보드와 상세 화면은 확인 불가 경고와 마지막 확인 상태를 함께 표시합니다. 기존 가용률 집계는 `INCONCLUSIVE`를 성공/실패 분모에서 제외합니다.
- 기준 주소에 다시 응답이 오면 영향을 받은 활성 모니터를 기존 스케줄러를 통해 즉시 재검사합니다. 대상의 실제 복구 판정에는 기존 복구 임계치가 적용됩니다.
- 재검사 후 선택한 채널마다 중단 구간과 정상 응답·대상 오류·확인 대기 수를 담은 요약 이벤트를 한 번 생성합니다. 재검사 대기가 2분을 넘으면 대기 수를 포함합니다. 복구 당시 이미 진행 중이던 검사들의 결과 저장은 먼저 기다립니다.
- 요약은 기존 outbox/재시도 경로를 사용합니다. 이벤트 중복 생성은 DB 키로 방지하지만 Telegram 응답 유실 후 재시도에 따른 중복 전달 가능성은 기존과 같습니다. 채널을 선택하지 않으면 이력만 저장합니다.
- 기능을 비활성화하면 진행 중인 연결 중단을 취소 처리하고 재검사합니다. 이를 실제 네트워크 복구로 알리지는 않습니다.

감시 PC 식별자는 기본적으로 OS 호스트 이름입니다. 필요하면 워커의 `NETWORK_OBSERVER_ID` 환경변수로 고정 식별자를 지정하세요. 같은 PC의 워커끼리는 동일하게, 다른 PC에는 서로 다른 값을 사용합니다. 감시 상태와 중단 이력은 DB에 저장되어 재시작 후에도 이어집니다.

## 반영 및 검증

DB 마이그레이션 `20260909050000_network_connectivity`와 `20260909050100_network_notification_constraints`를 적용하고 Prisma 클라이언트와 패키지·앱을 빌드한 뒤 API, 스케줄러, 워커, 웹을 재시작합니다. Windows에서 실행 중인 Node 프로세스가 Prisma DLL을 잠그면 해당 서비스를 종료한 뒤 클라이언트를 생성합니다.

네트워크 통합 테스트는 실제 인터넷이나 Telegram을 사용하지 않고 검사 결과를 주입합니다. 테스트가 전용 모니터와 outbox 데이터를 생성하므로 운영 워커가 중지된 상태 또는 별도의 테스트 DB에서 실행하세요. 설치의 기준 주소 설정은 변경하지 않습니다.

```powershell
$env:LINKALIVE_NETWORK_INTEGRATION = 'true'
pnpm exec dotenv -e .env -- pnpm --filter @linkalive/worker exec vitest run integration/network-connectivity.integration.test.ts
Remove-Item Env:LINKALIVE_NETWORK_INTEGRATION
```
